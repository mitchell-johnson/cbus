# SENLLA persistent late handler component

`senlla_late_forms.py` retains the concrete late Unit and its actual project
bridge, maintenance combo and broadcast collection. It implements the manual
PEC/PIR enable, maintenance, broadcast and maintenance selection handlers.
This increment does not complete director initialization, scalar bindings,
Show, Apply or the public whole-unit save path.

Predicates execute current native attribute getters at their source positions.
Reading a detached all-field context would miss or add managed ResolveChange
effects, so the runtime does not use a final graph as getter authority. PEC
collision runs while maintenance is inactive too. Unused enable groups clear
their Off attributes. Maintenance allocation retains the selected actual group
across Secondary, Group and MaintBlock setters, with the source scan's filters.

Maintenance Items retain real block and group objects. Population tests current
bank Active, broadcast and maintenance references per row; extra groups follow
the current manager order in the actual primary and secondary applications.
The bridge reads only the selected application's inventory. Item labels use
current owning metadata and explicit source display preferences.
Successful group and block ToString operations retain their outer
ResolveChange tails. A nil block group renders its source blank group text.
The actual retained block collection rearms before each native Count read.

Broadcast candidates use a real managed reference collection. Clear deletes
descending and each Add publishes synchronously. Later row predicates reread
current values after prior observers. List publication marks the Flash combo
dirty; it does not claim that a string list was rendered or that deferred
messages ran. Fallback selects the retained collection's actual first object.
An empty collection raises at the source index-error outcome.

The ordinary maintenance combo installs its Properties.OnChange callback at
the source setup position. The concrete no-HWND primitive delivers the
CM_TEXTCHANGED callback while SetItemIndex's click lock remains open. Nested
setters finish before the outer index comparison. Windows IndexOf requires the
actual Windows text provider, including identical strings; unresolved NLS
refuses and interrupts the owner. The normal fresh profile has no external
broadcast form callback installed.

Occupancy predicates and setters currently use the retained kernel's flag
model and bank event dispatch. Their Boolean values and order are preserved;
native managed flag attributes and their getter rearming remain a separate
owner dependency. Key collection and group-manager count identity, current
manager inventory and metadata notifications retain the kernel and bridge's
explicit source provider boundaries.

Authored tests exercise actual project objects, live bank fields, managed
getter rearming, callback mutation during list population and synchronous combo
allocation. Source receipts contain numeric method digests and authority
hashes. No original instructions, Windows UI or hardware were executed, and
the full test suite remains deferred for speed.
