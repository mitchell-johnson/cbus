# SceneManager buttons, Language composition and reconciliation

Three parallel implementation lanes deliver explicit SceneManager Add-button
callbacks, text-only Language initialization and declared source/obligation
reconciliation. The owning public CLI integration validates the combined
behavior through both cmqttd and cgate-mock. These are bounded major functions
within [issue45](https://github.com/mitchell-johnson/cbus/issues/45) and
[issue69](https://github.com/mitchell-johnson/cbus/issues/69); complete Toolkit
parity remains unfinished.

Button histories preserve actual source quirks: Action Add consumes the old
selected Trigger object and cannot select a newly created action from retained
Items; Lighting Add compares the returned Group address with application-choice
values and does not insert a scene item. Trigger Add performs only its explicit
selection/property callbacks. Cancelled and zero/multiple-selected-row outcomes
create nothing. Cancellation skips accepted OnOK name/address checks while
dialog setup still requires a free provisional address.

Text-only Language changes can precede the parent SceneManager sequence. A
sealed initializer replays the public Language prefix against the original XML
and checks its exact projected result. Initial scenes keep their original label
objects; an ActionSelector setter or explicit trigger-current refresh obtains
current text labels. A scene-current callback alone retains old DynamicAll. Later
Language changes cannot enter earlier views. Reset starts fresh ownership.
The modeled final Language boundary does not establish original per-row
notifications, COM scheduling or execution of an original form.

The reconciliation core joins declared source profiles, obligation variants,
bindings and pinned receipts. The public `coverage --reconciliation-bundle`
option reports unresolved mappings, stale artifacts, unknown handlers and
missing gates. Its scoped completeness cannot promote the repository census or
global parity decision. Supplied JSON cannot grant original or physical
acceptance. Source-record counts are accounting, not a functional denominator.

The focused release selection includes each owning module, affected retained
regressions, exact public cases on both backends and CI roster guards. Its
[mandatory module manifest](edlt-scene-controls-language-release-test-modules.txt)
is enforced in CI. The source and installed-wheel evidence partitions cover 932 unique parent
cases each: 919 pass and 13 have explicit environment or filesystem skips.
Each partition also contains 1,529 passing subtests. Disk exhaustion interrupted
the first attempts; their failed and unfinished cases receive credit only from
the successful exact continuations (110 source and 111 wheel parent cases).
The fresh wheel built for the interrupted attempt is reused and all 359 package
files are checked against source, ZIP and installation before and after the
continuation. The interrupted epochs remain failed in the evidence history.
The 48 total new public cases (24 per backend) pass, checking save uncertainty
without replay. These are focused partitions, not successful full-suite runs.
Exact outcomes and independent reviews are recorded in
[the publication receipt](../research/fixtures/scene-controls-language-reconciliation-owned-release-20261003.json).

Owned journeys check complete synthetic PP, SceneBucket, scene pointers,
static names, intermediate control views, independent whole-project structural
XML preservation and actual PROJECT SAVE/CLOSE/LOAD. Fresh offline subprocesses
check final snapshots; they do not establish backend restart. The structural
comparator preserves whitespace-only leaf text. It drops whitespace-only text
on elements with children and all whitespace-only tails, without consulting
`xml:space`, and does not prove byte-exact XML fidelity. No house endpoint, VM,
original instructions,
Framework binding instructions or physical device executes in this batch.
Rust code is unchanged and its previous required checks are retained only after
input/binary equality checks. The local full suites are not repeated.

Automatic host currency selection, notification cascades, modal/async behavior,
image/FONT/opaque DLTP Language profiles, broader source deduplication and
original/physical acceptance remain open. The broad ledger remains
18/42 = 42.86%, zero obligations are fully accepted, and the functionality
percentage remains unavailable.
