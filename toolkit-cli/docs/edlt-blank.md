# eDLT Blank widget selection

`EdltBlankWidget` reproduces one original bound **Blank** selection for KEYGL5 / 5055EDL / firmware5.5.00, using an explicit loaded model cycle. This is a widget edit. Toolkit **Reset Unit**, the physical **Factory Reset** command, a fully rendered dialog, and physical-device programming are separate scopes.

```sh
cbus-toolkit edlt blank-plan source.json --metadata lifecycle-cache.json --page 1 --position 2
cbus-toolkit cgate --host 127.0.0.1 --port 20033 unit --source /db//PROJECT/254/p/20 --lock-address //PROJECT/254 --dry-run edlt-blank --metadata lifecycle-cache.json --page 1 --position 2
```

The normal `unit` destination/save options apply. Plans expose all load, control, save and CRC changes before applying them. Cache JSON uses the [lifecycle cache schema](edlt-lifecycle.md): explicit absence differs from unknown facts, and populated level/dynamic-label cache facts are required where the original model reads them. This helper neither creates groups nor refreshes cache metadata.

The page convention is shared with other eDLT helpers. Page0 is standby, with positions1–5 identifying physical standby slots; a position immediately after an existing two-slice type11 is unavailable. Single-page mode exposes page1 positions1–5. Multiple-page mode exposes pages1–4 positions1–4; position5 is the navigation PageWidget, whose original type selector does not offer Blank. Raw `NavWidgetType` must already be0 or1. The original mutating getter that coerces other values to single-page mode is outside this explicit operation.

The lifecycle loads once, retaining eight scene objects, their cached item identities/private action selectors, all widget models, static strings and the original first-MRA global values. `blank_widget(loaded, slot)` issues a new `BlankedEdlt` receipt owned by that lifecycle instance. A copied, replaced, cross-editor or chained receipt is rejected. `prepare_save` then uses that issued control state without running AfterLoad again.

On a genuine stored-type change, the original selected WidgetData becomes BlankData and its functional RestoreLevel becomes0. Selecting an already loaded Blank preserves its model identity and RestoreLevel. The other31 record bytes remain intact. A legacy type1 may already have become Blank during AfterLoad, so `type_changed` describes the actual selection phase. Unknown stored types can carry BlankData without being stored0; selecting0 still performs the original type change.

BeforeSave retains its normal effects. Clearing the original first MRA widget does not reinitialize MRA globals from its next sibling. Removing the last functional widget may serialize Blank as end marker255, with later Blank RestoreLevels retained. Scene repacking, global normalization, remaining-widget forcing and five CRCs follow the same model save order. Stored static strings are preserved; clearing a widget can make its old label reference inactive. `after_load`, `after_controls`, `before_save` and final values remain separate in the plan.

Application validates every full snapshot and strict scalar types, replays a canonical plan before PP I/O, checks unit identity and stale state, and verifies complete PP readback. Ordinary failed edits attempt rollback while the connection remains usable. Interruptions retain their original exception identity and partial evidence without recovery I/O. `last_evidence` is cleared before each new configure preflight. CLI finalization separately preserves save-attempt, confirmed-save and cleanup outcomes; a confirmed database save remains recorded even when subsequent cleanup fails.
