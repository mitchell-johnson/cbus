# Wireless and Bytecraft L1 project reports

`project document` and `cgate database-document` recover the wireless input,
wireless gateway, advanced gateway and remote-control report bodies from saved
programming fields and existing project metadata. The unit factory admits the
50 wireless input types through 173 exact class/agent/firmware partitions,
the two gateways through eight partitions, and all seven remote types. These
counts describe registrations, not acceptance on physical units or every
possible saved state.

The wireless projection creates the original fresh model's sixteen key and
block slots. It retains the six-event order, the first matching global macro
template, decorator load/save remapping, byte and packed-nibble remote maps,
compacted scene order and native serial identity. Reports preserve duplicate
block groups, empty scene cells, raw tag text, source table fragments and the
wireless output loader's second percentage conversion. Timer fields are zero
only when the original fresh event constructor and command loader prove that
state. Missing consumed PP is a visible refusal; it is never replaced with a
factory default.

Gateway routing resolves adjacent and forwarded networks by `NetworkNumber`.
The saved native adapter preserves exact database Address identity separately
from physical Number and the source integer HTML projection. Distinct values
are admitted; ambiguous consumed Numbers and unresolved unknowns are marked.
See [native report identities](native-project-documentation.md).
The forwarding route consumes the contiguous existing prefix starting at
index one. Advanced gateway remotes retain page order and all sixteen action
slots. Remote bodies display their ten keys with each remote type's page and
label rules; dependency lists retain the original receiver and block order.
The advanced gateway's direct Input/Output/Other dependency methods are the
empty inherited implementations. Remote input dependencies come from bound
receivers. Action matching uses the stored Trigger `Level.Address`; `Value`
does not identify an action.

DIMPR12 also admits the original `TDIMPR12L1` / `TDIMPR12L1CGateAgent` partition
from 1.9.03 through 9. The old partition ends at 1.9.02. L1 adds one primary
application logic group and twelve attributes: bit 0 enables each association,
and bit 7 selects Min rather than Max. Output dependencies list every matching
channel first, then `Logic Group` or `Logic Group (Unused)`. Address 255 remains
an identity. A logic association does not change the source channel-unused
predicate. L1 inherits the existing 33 packed scenes and body/action rules.

The independent literal vectors contain complete invented native snapshots,
explicit unused applications/groups and full expected bodies:

- `research/fixtures/project-documentor-wireless.json`
- `research/fixtures/project-documentor-bytecraft-l1.json`

Static extractors reproduce the unit factory partitions, class shapes,
method fingerprints, macro/event tables and source checks from explicitly
provided pinned EXE/MAP files. Their receipts contain identifiers, hashes and
public labels; vendor files and instruction bytes are not committed. Historical
old Bytecraft receipts remain unchanged.

Focused tests cover exact body lines, ordered usages, firmware boundaries,
decorator and packed maps, all 256 L1 attribute bytes, missing metadata/PP,
undefined scene assignments and graph preservation. A missing remote that the
original loader would create is refused without changing the project. A scene
pair at byte 99 without its level, an unassigned gateway primary application
that leaves its key object undefined, and a selected missing scene are also
refused. These recovered saved-state rules do not establish original generated
page byte/visual parity, original loader execution, commissioning, physical
remote behavior or general Toolkit workflow completeness.
