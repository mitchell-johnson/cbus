`SENLLAOwner` retains the concrete `SENLLAInheritedOwner`, its prekey engine,
the actual project bridge, the live occupancy objects, the late Unit attributes
and the live bank adapter.
It admits the guarded 93-field SENLLA/5754PE/2.4.00..2.4.99 source profile. It
has no public preview/apply command and does not yet admit a complete save.
The Windows application, hardware and Windows text APIs were not executed for
this checkpoint.

Construct the inherited owner against an actual selected `ProjectDocument` or
native database with `defer_smart_observers=True`, then pass that owner and the
concrete persistent control provider to `SENLLAOwner`. The complete owner
requires this constructor mode: the historical detached Smart listeners are
never activated and later removed. Construction creates and binds all eight
actual occupancy objects before the surface banks bind their blocks. It
registers the late Unit and bank attributes before PP loading. `load()` performs the ordered source getters and
setters on those same objects. It returns the same owner at
`fresh_identification`, with the original outer Unit update balanced to zero.

The load schedule is prekey application/Area/metadata/scalars/block setters;
per-key allocations; CoreKey's final application refresh; CoreNeo Patch,
ControlAppGroup, Scene and key loading; NeoPro infrared, KeyDisable, Corridor
and Join loading; ST7 loading; then the surface loader. Disabled Patch still
loads Scene commands and selected Scene keys. The actual Scene collection
starts empty, and its objects are added at the source Clear/Add/fill positions.
Scene group creation and ascending Invoke action-level creation use synchronous
current canonical getters. KeyDisable's unused group lookup uses `create=False`

support Join editing. App255 is an actual bound metadata object.

Metadata lookup, creation, StorageSave, readback, descriptors, manager order and
active metadata observers are concrete project-bridge boundaries. A missing
observer provider refuses at its source position. Tests supply an explicitly
authored zero-extra-listener metadata profile; that profile is not native
workflow acceptance. A getter never authorizes a future cached object or a
replacement graph. Later application changes require the loaded Scene/hidden

## Actual occupancy and bank callbacks

Each occupancy object owns its InputKey reference, four Boolean attributes,

Inspection is separate from native getters. `current_occupancy_flags()` and
the nested `live_occupancy` snapshot read stored values without rearming

projection; `bank_graph_occupancy_authoritative` is false when the actual adapter
is installed. It cannot supply callback authority. The complete owner retains
the source SENLLA JoinActive=false branch and stable constructor-bound eight

The actual late macro/event decisions remain nil until their real source

The inherited string setter compares UTF-16 units. An astral character and the

## Current PP reads

The raw snapshot remains detached. The owner binds a current journal reader to
the inherited, prekey, block, allocation, Scene and key stages. Each read occurs
at the retained native getter position after earlier callbacks have completed.
The primary Application getter reads its blank-test and parse values separately;
the secondary mask is captured once before eight Boolean setters; allocation
masks are read again for each key. Each block reads its current index, stores,
timer bytes, expiry and group at the individual source positions. The Area
getter captures the current primary manager before reading PP; the Corridor
getter captures its PP address before reading the current primary application.

Guarded raw LightLevel has ten bytes. Current native cache admission is
explicitly bounded to 10..263 unsigned bytes, matching the journal and the
255-prefix-plus-eight-block rebuild bound. Current Count and indexed getters
accept that growth. Final programming still requires the ten-byte device
layout. Other current numeric reads retain their recovered counts and unsigned
widths. The bounded cache does not claim arbitrary native malformed-text or
unbounded-array behavior.

The earlier detached `BlockLoadPlan.requests()` remains a historical raw
component API. `current_requests(reader)` pauses at each setter; its indexed
level request records the raw projection only, and the owning executor reads
the current cache/index when reached. `rebuild_light_levels()` accepts the
captured current count. It is a serializer building block, not owning save
execution.

## Source-position save building blocks

The key engine can issue individual PP assignment, append and indexed-write
requests. It captures CoreKey allocation/block values first, then CoreNeo Scene
table/pointers, then key values. A later nil-trigger getter can create metadata
and invoke callbacks; those mutations do not retroactively change earlier PP
captures. NeoPro's secondary mask is captured later. A complete save owner must
capture and rebuild the CURRENT indexed LightLevel array at the earlier CoreKey
position, before the key serializer's callbacks. Passive `block_values()` after
key serialization does not establish that earlier capture.

`SENLLAParameterJournal` distinguishes the loaded PP cache, the original
physical baseline, and the fresh synchronous SAVE-agent cache. Normal source
LoadPP/save verbs omit LiveAgentMode, so the loaded agent is freed and a fresh
SAVE agent supplies 86 actual constructor attributes. String/array caches start
blank, integer and Boolean caches start zero/false, and seven protected raw rows
have no SAVE-agent attribute. JP/SR/LP/LR use native ascending append operations;
they are not seeded from the loaded arrays. LiveAgentMode and pending asynchronous
agent contexts are outside this cache-lifetime proof.

All actual SAVE-agent attributes become edited before BeforeSave. Source
programmable filters are distinct from internal cached writes. Protected cached
values can change and remain unsent. The journal refuses physical programming
until all filters and the edited-state preparation are established and every
eligible value fits its device layout. Logical schema/native-agent naming is
not protocol alias proof.
