# Widget control adapters and automatic Global Programming

This batch adds three software workflows to the Python Toolkit CLI: source-owned
label/status callbacks for six AppGroup widget families, explicit Scene widget
callbacks, and image-aware automatic metadata for Global Programming. The public
commands use the existing cmqttd and cgate-mock database/PP surfaces; no Rust
implementation changes are required by this batch. Full Toolkit parity and
original/native/hardware acceptance remain unfinished.

## Implemented behavior

Enable, Timer, Shutter, MultiLevel, Fan and Room Courtesy parent operations now
accept ordered `label_controls`. Bindings use exact issued identity, owning
parent, complete postordinary PP, operation position/history, dynamic rows and
all 64 retained names. Enable uses application203 and its unchanged-index rule;
the other siblings retain their own application ranges, record offsets and
status choices. Fan/MultiLevel's four static status controls use
ComboBoxStaticText callbacks. Shutter uses the inherited generic status choices
actually consumed by the source, rather than its unused alternate list.

A type change can release a static name for a later ordered widget allocation.
The shared parent permits that causal reuse while keeping other PP ownership
exclusive. Pending text refuses preparation/save. Speculative static allocations
remain local until the complete callback branch succeeds, including later
invalid-choice and pending-close failures. Final parent normalization, CRCs and
one PP SAVE keep their existing ownership.

Scene `scene_controls` expose exact observed scene/type/variant/macro choices,
status-text callbacks, cycle row selection, current-cell actions, explicit
getter reads and radio/button callbacks. The source SceneData hides its index
properties; changing the base display type does not silently reset those stored
indices. A `get-view` does not invoke the mutating SceneCycle getter. The explicit
cycle getter accepts raw0..8, stops at the first invalid byte without rewriting
that byte and clears later slots. At the native parent save boundary, active
references still require configured scenes0..7. No implicit host selection,
notification scheduling or cycle read is synthesized from a journaled request.
Earlier SceneManager edits provide the actual names for later Scene bindings.
Ordered preparation also follows ordinary intervening widgets after a
SceneManager edit. An already-Blank slot keeps its stored restore level; a real
type change or fresh Reset uses the canonical Blank transition instead.

Global Programming now prepares an ordinary source from one exact native
project snapshot, parameter order, current Language and explicit SHA-bound
project/DLTP image providers. The in-process source association independently
retains exact source/context/owner/provider identity; clearing or substituting
public dataclass fields cannot downgrade an automatic source to manual mode.
All16 category masks preserve the original declared payload ordering, including
forced checksum behavior with no selected categories. Targets keep their own
Language, static strings, scene data, widgets and unrelated PP unless a chosen
category explicitly includes the field. Source units are excluded from the
bounded distinct same-project destination list.

The coordinator checks complete source/project freshness before writes and
all874 PP plus the complete canonical project graph after each target. The
graph profile preserves ordered elements, exact attribute values, comments, processing
instructions, leaf text and nonblank parent text; indentation-only text around
child elements is ignored, attribute ordering is not compared and xml:space is
not interpreted. Source XML hashes
remain exact. Target models are not initialized as source lifecycles, and no
label transfer, image upload, Language edit or factory preparation is inferred.
A lost successful save stops without replay or a second target; its outcome is
reported uncertain despite a separately observed accepted upstream save.

Read [widget schemas](edlt-widget-control-adapters.md) and
[automatic source metadata](edlt-global-image-metadata.md) for complete command
examples. The implementation is constrained by the existing KEYGL5/5055EDL/
5.5.00 source/specification profile and bounded image decoder.

## Evidence and validation

The frozen 42-module source and isolated-wheel attempts each recorded **609
passing parents, one failing parent, 15 provisioning skips and 1,030 passing
subtests**. The failure was the daemon's 16-mask journey stopping at
`PROJECT COPY IMGLOBAL GB13`: thirteen retained synthetic backups approached
the explicit 32 MiB repository limit. Its earlier masks0–12 completed; mask13's
preview passed and its apply stopped before either destination save. This is
retained failed evidence, with no claim that the complete 42-module gate passed.
The selected modules cover the new features, affected parent
and Global Programming regressions, compatibility metadata and public journeys
on both owned Rust backends. The current successor selects only the changed
Global interaction module and eight metadata modules, in source and a fresh
installed wheel. Its exact results and package/source comparisons are in
[the release receipt](../research/fixtures/widget-adapters-global-owned-release-20261003.json).
Unaffected successful cases from the broad attempt and the targeted successor
retain distinct snapshots and overlapping counts; they are never added together
or presented as one current 42-module pass. The full Python suite is not part
of this batch. No Rust code changed, so the unchanged binaries and
previous required Rust gates are pinned separately rather than rerun/recredited.

Three parallel producers supplied separate source proofs and independent
literal vectors. Read-only source extraction consumes pinned managed bodies and
decompiled declaration spans without executing original instructions. Peer
review crosses the producer boundaries before root integration/publication.

The public widget test scope covers all six families, their combined parent, Fan's
four static status fields, Scene selection/cycle, earlier SceneManager names
and intervening Timer edits before later Fan/Scene controls,
pending-text refusal and loss after an actual accepted save. They check all844
PP names for complete unowned-state preservation, opaque target bytes, named
literal control/static allocations, multiple-page navigation, retained restore
levels, end markers and unrelated
project objects and explicit save/close/load durability. Other allowed owned
record bytes, WidgetGroups and checksum values have their separate component
and parent regression coverage; these public journeys do not add independent
literal value oracles for those fields. Global journeys cover
all16 masks on two divergent targets and loss after the first accepted save,
checking full874 PP, literal ordered payloads, unrelated graph preservation and
save/close/load. The current Global fixture also verifies every owned backup's
pre-apply copied graph, all three 874-PP units and saved close/load image before
deleting that one test backup. The primary project's graph and project inventory
remain unchanged by cleanup. Loss journeys perform no such cleanup after an
uncertain save. This bounds the fixture without removing the product's 32 MiB
limit or proving capacity parity; [issue77](https://github.com/mitchell-johnson/cbus/issues/77)
tracks that separate gap.
Nine pure parent regressions separately cover intervening Timer/Scene edits,
already-Blank restore retention, real Blank type changes and the previous
no-controls behavior. These owned fixtures use loopback/inert MQTT/scripted PCI with
closed physical-interface traps. They do not contact the house network.

The Global pure vectors retain synthetic foreign `Opaque` elements; the owned
FILE/RESTORE importer rejects those Group extensions. Public interaction setup
therefore removes only those declared synthetic children, adds required native
TagNames and starts preservation from actual post-RESTORE DBGETXML. This is a
separate admission boundary and does not establish arbitrary extension or native
repository parser equivalence.

Retained failures include independent AppGroup commit-then-refusal cache leaks,
Global mutable source-association downgrades and provider-identity regressions,
Scene fixture default/choice mismatches, root synthetic debounce and operation
spelling errors, root ordered static allocation conflicts, owned import fixture
schema refusals and a public preview JSON-path assertion error. The known
wrong-project export preconnect regression remains separate: the current CLI
refuses a SHA-valid foreign-project provider before connecting. Successors keep
their exact current source pins and actual results; predecessor passes and red
attempts are not rebound to changed bytes or added to final counts.

The first integrated source and wheel attempts each recorded 596 passing parent
tests, one failing daemon Global Programming apply, 15 explicit provisioning
skips and 1,030 passing subtests. That apply exceeded the test process's 30-second
outer budget after both destination saves and the project save had returned

successor uses a bounded 180-second process budget and retains partial wire/output evidence
on timeout. These failed attempts remain predecessors, without acceptance credit
for the current source. Their audits also refused passing-body credit for the
historical five-case vendor-only Global CLI module. Its cases remain collected
and individually reported as skips in the successor selection.
The next source/wheel attempts were deliberately interrupted after a reviewer
found stale packaged capability references and the late-mask process budget
needed adjustment. They retain actual partial outcomes and cleanup evidence,
with no complete acceptance credit. The final selection uses the corrected

The subsequent capacity refusal is separate from those earlier timeout and
operator-interrupted attempts. The previous published CI run also ended
