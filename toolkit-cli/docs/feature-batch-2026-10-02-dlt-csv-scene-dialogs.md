# DLT conversion, CSV families and SceneManager Add dialogs

This batch adds 120 DLT-target conversion directions, 91 additional bounded
CSV unit types, and ordered accepted/cancelled eDLT Trigger/Action Add-dialog
operations. Current registration admission is **243/292 conversion pairs** and
**126/262 CSV types**. These are specific software scopes; the category ratio
and fully accepted-obligation counts are unchanged.

The new directions comprise fifteen classic, ninety-six modern and nine DLT

source-pinned Toolkit registrations. The implementation preserves literal
constructor order, duplicate assignments, label-zero behavior and

one PP save, durable uncertainty and read-only recovery. The earlier 123 pairs
retain their historical native evidence. The additional 120 have static,
synthetic and owned-service evidence; they have no new original GUI, cold
native conversion or physical acceptance.

classic Key, older Neo, NeoPro and wireless input/remote/decorator classes.

## SceneManager accepted and cancelled Add operations

The automatic metadata path admits ordered `add-trigger-dialog` and
`add-action-dialog` rows. They model default acceptance or explicit
`cancel: true`, first-free addresses 0–254, reserved address 255 and editable
`Trigger Group N`/`Level N` seeds. Duplicate checking, entered-name comparison
and stored-name trimming follow the retained source contracts.

Trigger Add followed by Action Add creates the accepted Group and Level 0;
it does not invoke the Action Selector getter before allocation. Existing
getter side effects remain independently visible. Requested operations and
dialog outcomes bind the plan, and accepted rows compose through the existing
SceneManager and parent transaction rather than a separate save path.

Dialog validation consumes explicit Project TagName; command selection uses
Project Address. The modeled Rust project producer emits TagName from its
authoritative `project.name`, matching its archive serializer. This does not
recover arbitrary wrapper metadata previously ignored by RESTORE.
New-dialog preflight refuses literal `#`, whitespace changed by command
tokenization and XML 1.0-forbidden U+FFFE/U+FFFF before backup or mutation.
Ordinary XML-representable Unicode remains admitted. These transport fences
are declared software input limits.

Metadata creation, `PP SAVE_TO_SOURCE` and `PROJECT SAVE` are separate
boundaries. A new Level is initialized once. Known objects can be removed
before a save attempt; uncertain creation and save outcomes retain evidence,
and saves are never replayed. Application Add, separate Corridor/Activation
Add, complete interactive form binding/images and physical display behavior
remain unfinished.

[automatic metadata](edlt-scene-metadata.md) and
[SceneManager editing](edlt-scene-manager.md).
