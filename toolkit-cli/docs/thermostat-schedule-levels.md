# Thermostat scheduling levels

`cbus_toolkit.thermostat_schedule_levels` provides a retained model of the original thermostat dialog's inner `CreateLevels` operation. It creates missing scheduling addresses 1 through 31 for one explicitly selected group. The fixed actions are `Enable`, `Disable`, and the original spelling `Overrd`.

```python
from cbus_toolkit.thermostat_schedule_levels import ScheduleLevel, ScheduleLevelsEngine

engine = ScheduleLevelsEngine()
state = engine.load([ScheduleLevel("existing-1", address=1, value=205, tag="Keep me")])
outcome = engine.create_levels(state, "Enable")
assert outcome.complete
assert outcome.state.levels[0] is state.levels[0]
```

An existing level is selected by **Address**, independently of its Value. Existing labels, values, order, and record references are retained. Missing levels append in address order. Each receives Address=Value, then its default `Level N` label and first save, followed by its `Sched ACTION Zone:…` or `Sched ACTION Zones:…` label and second save. Calling another action on the completed retained state preserves the first-created labels. Identity strings are model record identifiers; they do not independently establish an original object pointer or native OID.

The accepted input domain has unique byte addresses 0 through 255, byte Values, valid Unicode tags up to 128 characters without NUL, nonempty identity strings with the same bound, and an initial save-lock count 0 through 2. The list is bounded to 256 records and is copied into a tuple. Existing tags are opaque retained values; this API does not recreate original parsing or Unicode formatting for supplied tags. Only the 31 fixed scheduling labels are generated. `level_to_zones(address)` exposes those exact labels for addresses 1 through 31. The general byte-address/count domain is composed from the original address-search loop and the explicit guards; captured original examples reach 34 retained records, including addresses 0, 32, and 255. A portable regression separately exercises all 256 byte addresses.

`ScheduleLevelsEngine.load(levels, *, save_lock=0, pending_save=False)` issues immutable state owned by that engine. `create_levels(state, action, *, level_save=None, storage_save=None)` returns `ScheduleLevelsOutcome`; `outcome.state` is the next issued state and `outcome.events` contains ordered immutable phase snapshots. The original model lock increments before lookup, and project-save requests while locked set the pending flag. The normal final unlock decrements before a pending flush and clears pending only after that flush returns. `end_save_lock(state, *, storage_save=None)` exposes an explicit normal outer unlock for a positive retained lock count. These model flags are not native C-Gate locks.

With callbacks absent, `scope` is `model_only`; all saves and completion counters are modeled observations, and no storage I/O occurs. Supplied `level_save(level, state)` and `storage_save(state)` callbacks run at the observed save boundaries with detached copies of the state and level records. Altering those snapshots is rejected after a normal return; if the callback raises, its first exception remains primary and the trusted work state is retained. Callback return values are ignored. A failure stops there and rethrows the same exception object, including `KeyboardInterrupt` or `SystemExit`. The engine keeps `last_error`, `last_outcome`, and `last_evidence`; evidence export or attachment failure does not replace the original error. A partial outcome has `complete=False` and its state cannot be resumed. There is no retry, rollback, automatic unlock, or claimed Delphi exception unwind. The two original denial cases were deliberately stopped at provider boundaries, so their partial states are evidence about those boundaries rather than original error-handler completion.

The original comparison uses 14 case outcomes: 31 standalone zone labels, three empty-group actions, existing/mixed levels, repeated actions, nested/prior-pending locks, two planned save denials, and two extra-address cases. Constructors, strings/variants, collection callbacks, and bottom storage writers were explicit owned providers; original CreateLevels, FindLevelByAddress, address/value accessors, Add wrappers, and project lock/save logic executed as unchanged EXE instructions. The first failed instrumentation run remains separately preserved and is not counted as a pass.

The outer button, enable/group-selection predicates, UI cursor/delay handling, original service factories, physical communications, and native persistence remain separate evidence and APIs.
