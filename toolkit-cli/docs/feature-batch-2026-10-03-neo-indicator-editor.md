# Per-unit Neo indicator editor

This batch advances [issue 39](https://github.com/mitchell-johnson/cbus/issues/39)
with a separate per-unit indicator workflow for 30 ordinary Neo profiles at
firmware 2.5.00. Existing Unit Magic bulk indicator commands keep their behavior.
Read the [operator contract](neo-indicator-editor.md) for commands, control
domains, exact profile bounds and normalization effects.

Ordered controls preserve physical LED identity, colour-cell availability,
checkbox callbacks and slider change suppression. Plans project the panel's
load, controls and owned save once, including invisible array slots, Classic
hidden defaults and Reflection colours. They bind the exact unit identity and
recompute serialized history before schema/freshness checks and PP staging.
The native command requires an existing database source and saves once;
it does not retry a lost save response.

The [static annex](../research/fixtures/neo-indicator-editor-source-review.json)
and its reproducer pin 187 method ranges, 601 virtual dispatch slots,
30 profile constants, one form resource and 30 decoded specification layouts.
An independent parent run checked those pins against the retained original
EXE/MAP and private schemas. This reads original bytes; it executes no original
instructions, native service or hardware. The literal expected results in
the tests are authored from that bounded source contract.

The focused backend roster covers seven contexts on both maintained Rust
adapters: ordinary Neo, Reflection, Classic, Saturn, Decorator, Avanti and
catalogue 5041NMML. Four additional cases drop the response after a successful
save. Each normal journey compares offline planning, public dry-run staging,
one save, fresh PP reads, project save/close/load, unchanged surrounding graph
content and literal packed bytes. Refusal cases cover malformed/tampered
plans, callback order, stale parameters and identity changes. Closed synthetic
network contact traps distinguish database edits from device operations.

The final seven-module source and fresh installed-wheel selections each pass
**108 parent tests and 735 separate subtests**, with **10 provisioning skips**.
All 18 public backend cases pass in each environment. All **2,728 scoped
inputs and both Rust binaries** remain unchanged across execution, and all
**378 package files** match source, wheel and installation. The installed
console also produces the literal expected plan with `PYTHONPATH` absent.
Six fresh modeled compatibility receipts, the generated register and the skip
census pass their checks. The census records 727 test modules and 259 required
native tests; this batch does not run that native gate. The
[release receipt](../research/fixtures/neo-indicator-editor-owned-release-20261003.json)
binds the exact candidate bytes, selection IDs, skips and retained raw outcomes.
Independent review checked all 36 backend receipts without discrepancies.
The 28 normal journeys retain packed readbacks and project reopen evidence;
the eight lost-response journeys retain fresh parameters/XML and passing
packed-value assertions, but not separate direct-owner packed-read receipts.

The skips are the optional new static-input check, the older vendor-schema
CLI case, four original/native input-option cases, older original-binary/help
provisions and two native extended-macro cases. The new static verifier passed
separately with the pinned original files; it does not turn original-runtime
or native-service skips into acceptance.

The first source and wheel attempts each had four setup failures before Rust
startup, alongside 104 parent passes, 735 subtest passes and the same ten skips.
The temporary Python launcher had not executed the Rust binary when its
15-second deadline expired. The test harness now passes schema arguments to
the owned binary directly, retaining its timeout and ownership checks. No
editor logic or literal expectation changed for this repair; the underlying
interpreter stall cause is not claimed. Failed logs and raw evidence remain
separate from the passing final runs. One older CLI test helper was also fixed
to respect the selected source/wheel environment instead of forcing `src/`.

Whole-parent Apply/Cancel history, KEYE's remapping, other firmware/models,
brightness-group selection/creation, original-runtime comparison and physical
acceptance remain open. This is progress on the panel, not closure of issue 39
or a claim of complete Toolkit parity. Full-suite checks are intentionally
excluded from this batch's local scope in accordance with the user's request
for focused validation.
