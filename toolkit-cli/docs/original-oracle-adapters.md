# Explicit original-model adapters

The research harness can select the original Toolkit 1.18 Windows assemblies with `CBUS_ORIGINAL_MODEL_BACKEND=windows`. Omitting this variable retains each migrated test's existing Docker path and environment gates. An unavailable or failing backend does not cause a fallback.

`research/original_oracle.py` provides `OriginalModelOracle(source, app, *, backend=None, references=(), gui=False)`, with `run(arguments=(), files={name: bytes})` and `run_result(...)`. It accepts one owned C# source, explicit original DLL references, literal arguments and byte-valued input files. `run_result` retains native failure output. `run` requires exit zero. Instances have separate probe/file namespaces; calls on one instance are sequential.

The Windows path verifies the staged original-assembly manifest and compiles an x86 probe through the owned file-job bridge. The bridge makes an immutable, flushed command snapshot before process start and does not replay admitted jobs. A lost result remains uncertain. See [the Windows oracle contract](windows-native-oracle.md) for admission, expiry and provenance details.

The Docker implementation uses structured process arguments, a pinned Mono image, a read-only original-assembly mount and no network. GUI selection explicitly requests `xvfb-run -a`; the adapter neither installs Xvfb nor interprets an arbitrary shell command. Existing test-specific Docker branches are retained during migration.

The argument grammar accepts simple literal tokens. A narrow additional form, canonical `@0` through `@64`, supports the original static-label probe's index syntax. It rejects leading zeroes, larger indices, whitespace and shell metacharacters. That form uses the same compiled, source-pinned Windows probe and immutable bridge job; it does not change the frozen bridge helper's public grammar. Input data cannot replace source, assemblies, executables or command scripts, use reserved Windows device names, or collide by case.

## Focused migration coverage

General was the initial shared-adapter pilot. The next batch adds explicit branches for Display, Standby, Colours, Measurement icons and Activation. Their production implementations and original C# probes are unchanged. The Standby `mono(...)` helper imported by Navigation is unchanged, so this batch does not migrate Navigation indirectly.

The batches compare the existing literal expectations, complete original PP snapshots and CRCs, independent native C-Gate raw bytes, and database save/close/load results. They retain each helper's direct setter/save-stage scope; they do not expand it to the full editor load lifecycle. Tests use unique owned closed projects. Metadata-absence assertions and hidden-field preservation remain part of the existing tests. These results do not establish physical eDLT programming or control.

Focused execution requires an already verified Windows bridge and an owned native C-Gate endpoint, plus explicit `CBUS_TOOLKIT_EXE`, `CBUS_UNITSPEC_DIR`, `CBUS_CGATE_TEST_HOST` and `CBUS_CGATE_TEST_PORT`. The Measurement graphics test also requires the existing `pefile` and `unicorn` dependencies. Native reports can be written separately using `CBUS_EDLT_DISPLAY_REPORT`, `CBUS_EDLT_STANDBY_REPORT`, `CBUS_EDLT_COLOURS_REPORT`, `CBUS_EDLT_MEASUREMENT_ICONS_REPORT` and `CBUS_EDLT_ACTIVATION_REPORT`. `CBUS_EDLT_STANDBY_VECTOR_REPORT` separates its literal output. The General pilot predates those report-isolation changes; its fixture records the retained log/report limitation explicitly.

Batch 1 passed **49 tests with no skips** on Python 3.13.14 and 3.10.20. Each run checked 4,746 original model output rows and 95 native cases: Display 27, Standby 34, Colours 9, Measurement icons 7 and Activation 18. Every native case compared all 874 PP fields and five CRCs. The native case reports match between the two Python versions. The separate unchanged graphics probe exercised 255 original DLL selector calls.

A read-only comparison with frozen test inputs confirmed all 352 assertion expressions, test decorators/environment gates and existing Docker command strings are unchanged. Standby's imported helper is byte-identical. The 19 pinned adapter/test/probe/production/bridge source hashes remained stable across both runs. No full suite or Docker run was performed for this batch.

Quick Status now uses a separate `research/original_source_oracle.py` adapter. `OriginalSourceSetOracle(sources, app, *, entry_point, backend=None, references=(), gui=False)` accepts two to eight ordered, distinct owned C# files and a validated explicit entry point. Each result receives fresh evidence dictionaries backed by immutable internal hash pairs.
