# NeoPro saved-project CSV

The saved native XML adapter admits **KEYB2, KEYB4 and KEYB6 at exactly firmware
`2.5.00`**. This adds the bounded family to the existing offline and live CSV
commands. It is a read-only report projection; it does not load programming,
create missing database records or save the project.

```sh
cbus-toolkit toolkit-database-csv saved-project.xml \
  --native-xml-project //PROJECT --output new-report.csv
cbus-toolkit cgate --host 127.0.0.1 --port PORT database-csv \
  --project //PROJECT --output new-report.csv
```

Use the actual saved project name and chosen server endpoint. Unit, explicit
multi-unit and Network selection remain available through the existing
`--native-xml-unit`, `--native-xml-units`, `--native-xml-network` offline flags
and the corresponding live selectors. Live export obtains one complete
`DBGETXML //PROJECT` snapshot, then validates the entire selection before
creating the output file. A failed read or unsupported late Unit creates no
partial report, and the read is not retried. Existing output files are never
overwritten.

## Admitted snapshot

Each selected Unit must contain its ordinary report identity fields and exactly
one of each consumed PP parameter:

| Parameter | Required stored shape |
| --- | --- |
| `Application` | Two byte values: primary and secondary addresses |
| `GroupAddress` | Exactly eight byte values in block order |
| `SecondApplicationBlocks` | One byte mask |
| `AreaGroupAddress` | Exactly `255` |

The primary Application and its Area 255 Group must exist. A secondary address
other than 255 must identify exactly one existing Application, even when its
mask is zero. A nonzero mask with secondary 255 is refused. Every consumed
Group must resolve uniquely in the application selected by its block bit.
Duplicate consumed parameter names, application/group addresses or group OIDs
are refused. Omitted Group OIDs use canonical application-qualified paths;
same-address Groups in different Applications stay distinct.

Bits 0 through 7 select the secondary Application for the corresponding blocks;
unselected blocks use the primary Application. All eight block associations
are retained in order, including repeated Groups and unused 255 references.
All eight are visible in CSV, independently of the physical key count. Group
columns 9 through 16 are `<N/A>`. Area always comes from the primary Application,
including an all-secondary mask and separate Group 255 objects in both
Applications. The inherited cached projection retains its two ordered Area
observations even when the Area column is omitted.

Public `--cached-projection` now admits these three types through the strict
[cached v2 identity contract](toolkit-database-csv-neopro-cached.md). It names
primary/secondary Applications, their Group membership and the block mask;
Area lookup uses primary membership rather than cache order. The legacy v1
JSON remains refused for NeoPro because its tags cannot establish that identity.
Existing families retain their v1 contract. The native adapter derives the same
explicit context from the selected XML Applications.

The existing report serializer keeps column order, quoting and CRLF output.
Network selection sorts Units by numeric address; project selection retains
Network document order and applies that Unit sort within each Network.
Explicit Unit selection retains caller order. These are the declared snapshot
policies, not a new claim about original Toolkit manager history.

## Evidence and boundary

The [exact source/row/wire vector](../../rust/testdata/vectors/toolkit_database_csv_neopro.json)
pins the three factory registrations, class/agent virtual methods, method-span
hashes, eight-block/secondary-mask/Area rules and synthetic literal CSV bytes.
The [current static registry](../research/fixtures/toolkit-database-csv-neopro-registry.json)
was generated by the maintained extractor after inspecting the pinned Toolkit
1.18 EXE/MAP bytes. Original factory and report facts are unchanged from the
historical registry; only modeled admissions and their refusal descriptions
change. The historical 2026-09-30 receipt remains intact.

The new focused module is `tests/test_toolkit_database_csv_neopro.py`. Its
public subprocess checks are runnable against source and an installed wheel;
live framing uses an owned scripted loopback peer. The fixture covers all
three types, primary/secondary masks, separate Area identities, duplicate
associations, mixed Network order and atomic whole-project refusal.

Static inspection executes no original instructions. This feature does not
establish a fresh Schneider C-Gate cold LOAD/readback comparison, original GUI
report or Windows manager/locale behavior, physical behavior, or support for
other Neo/NeoPro types and firmware. Those broader obligations remain in
[#56](https://github.com/mitchell-johnson/cbus/issues/56).
