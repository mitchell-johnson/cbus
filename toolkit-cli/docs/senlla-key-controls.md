# SENLLA persistent general-key controls

`senlla_key_controls.py` implements the internal programmatic general-key
control slice against the same `SENLLAKeyEvents` objects. It retains eight
combo states, root identities, current template pointers, render guards and
pending message positions. It derives the native root selection, missing
template reset to16, group nil representation, extension visibility and
ordered broadcast candidates. Real template setters run synchronously through
the key engine, including its nested callbacks.

This component is not a complete fresh-form owner or a public configuration
workflow. Windows framework effects, exact list comparison, group rebinding,
actual collection listener delivery and message scheduling remain causal
dependencies. Supplying a callable that returns None does not establish that
those native effects executed.

## Entry and identity

Create `ControlBindings` with the actual primary and secondary function-root
objects, their ordered canonical `FunctionChoice` objects and actual resource
text. A `FunctionRoot` has persistent identity; equal contents do not make two
roots the same object. Template descriptions are stable canonical descriptions
in this slice. Descriptions of one template must agree between roots. Duplicate
labels on different template objects are allowed.

Supply the eight actual current root links and eight `ComboState` values:
ordered items, selected index, actual Text and list-dirty flag. Also supply
actual group nil text, extension visibility, subset names and key0/key1 block
override flags. These are the completed initial function-binding state, not
arrays inferred from the desired PP output. The fixture and tests use explicitly
supplied conditional entry states; they do not prove the preceding raw-loader
or form-constructor history.

Call `controls.attach(engine)` after `fresh_function_bindings()` and before
`install_m8_hooks(control_dispatch=controls)`. The admitted fresh M8 entry has
initializing true, no ST7 broadcast collection and no light frame. Stable active
scalar/list controllers use the fixed `MacroFunctionTemplate` expression,
`fssNone`, no include predicate/event, empty substitutions and no optional nil
row. Form construction, expression parsing, inactive resume and destruction
are outside this slice.

The scalar observer registers before the later M8 general/template hooks.
It rereads CURRENT Template on key publication, compares object pointers and
updates its current-target subscription before rendering. Equal pointers skip
the root-derived render; direct publication from the current target renders
without a pointer change. Thus a newer general hook can reset an intermediate
template to the original16 before the older scalar observer sees it.

After the actual M8 hook sequence, call `finish_m8_guard()` at the native
initializing-flag clear. Bind the actual later-created ST7 `f8` collection with
`bind_broadcast_root(root)`. Creation does not replace an already selected nil
combo root. Bind the actual completed light frame and its current block list
with `bind_light_frame(broadcast_items=...)`. These explicit lifecycle calls
must occur at their source positions, rather than being inferred from final
state.

## Synchronous general callback

The Base branch refreshes direct block-override flags and the subset name.
For this SENLLA class, both subset names are `SENLLA`, MaximumKeyCount is-1 and
InfraredBankPropertyEnabled is true. The normal function root is primary for
application state0 and secondary for1/2. A nonnil template absent by canonical
object identity from that actual collection invokes the real template16
setter. The loop rereads CURRENT Template and does not stop at the first match.

The paired29/30 key0/key1 override requires both keys to reference block
index1. The ordinary SENLLA subset cannot retain that pair. An explicitly
supplied existing pair, or a prior true override being cleared, requires the
actual key/block consumer binding through `SetPairedKeyBlockOverrides`.

`UpdateGroupCombo` runs only when initializing is false. The remaining order
is group nil text, extension visibility, empty pairings and the ST7 multisensor
primary-group reset exit. Then the ST7 selector rereads BroadcastActive and
CURRENT broadcast block membership. A match selects the actual broadcast root,
which can still be nil during early M8 initialization. Otherwise it rereads the
application state and selects primary or secondary. If the light frame exists,
the broadcast candidate loop follows. Engine-owned recall runs after this
callable returns.

Each callback return is followed by the source-required CURRENT reads. The
broadcast loop excludes the current active maintenance/broadcast conflict and
blocks used by a current Scene23/24/25 or occupancy flag. Clear/Add collection
notifications occur at their real positions inside ItemsBegin/End; an earlier
Add callback can change a later candidate.

## Rendering and unresolved primitives

The render guard covers list population, display and enable state. List
population captures count, but reads the CURRENT list root and ordinal for
each row and again after Add when testing selection. It clears dirty, performs
the actual text/cache fallback, ends ItemsUpdate in a finally block, selects
all and invalidates the control. RenderDisplay obtains CURRENT description,
asks actual Items.IndexOf, sets the index, then rereads CURRENT description
before SetText. An index callback can change the template while the same-control
render guard suppresses a nested render.

`dependency_executor(request, engine)` must execute each requested primitive
against this same live owner and return after its synchronous callbacks.

| Kind | Required actual work |
| --- | --- |
| `framework` | ItemsBegin/Clear/Add/End, index/Text/cache fallback, visibility, nil representation, SelectAll, invalidation and enable effects. |
| `binding` | Actual SetFunctionListRoot notifications, list active transitions or the full source group-combo rebinding branch. |
| `collection` | Actual broadcast Clear/Add notifications or function collection publication in its real current listener order. |
| `comparison` | Actual Items.IndexOf; return the integer index or-1, including duplicate-label behavior. |
| `description` | Actual current template description outside the bound collections; return text. |
| `model_binding` | Actual key/block override consumer fields for the exceptional paired context. |
| `scheduler` | Actual PostMessage WM0x426 at the owner-issued position. |
| `callback` | Actual HandleComboChange, including its RenderDisplay and conditional AfterChange effects. |

Every kind except comparison/description returns None. Final-state arrays,
approval Booleans or replacement graph dictionaries are rejected. A missing
dependency interrupts both controls and the engine; committed source effects
are retained and the owner cannot resume or save. ItemsEnd and the render-guard
finally blocks preserve native exception timing within their admitted scope.

An unequal root commits the selected identity before requesting actual
SetFunctionListRoot. The binding executor issues `list_changed` at each real
list/root callback position. Its exact multiplicity is not inferred as one.
An actual nil root has tracked-handle count0; this does not make the scalar
template nil or replace the current description with nil text.

`collection_changed(root, choices)` supplies one actual Clear/Add event's
CURRENT contents and requests its real listener delivery. It must be called
at each native mutation/notification position; a final-contents replacement
cannot replay LoadFromCollection's earlier Clear/Add events. The executor delivers
`list_changed(key, root)` at each actual callback position. The kernel does not
invent an aggregate ascending key loop or reorder other listeners. Such list
callbacks mark dirty and update enable; they do not synthesize a template
selection or a list render.

`post_combo_change(key)` is called only after the owner executes the real
DoIndexChange BeforeChange/CanChange/scalar-setter branch. It records the
message before requesting native posting. `deliver_combo_change(key)` consumes
one pending message for that actual owner-issued key delivery. The kernel does
not infer global delivery order from posting order or implicitly drain messages.
Programmatic SetItemIndex and exact Items.IndexOf do not imply a manual selection
or a model setter. The full scheduler and framework trigger route remain
required for a complete owning workflow.
