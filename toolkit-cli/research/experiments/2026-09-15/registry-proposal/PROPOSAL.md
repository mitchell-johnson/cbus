# Registry conditions: supplied facts and a twelve-call admission pilot

Status: proposed, not executed. The accepted conditions v1 API, its 61-test checkpoint, and all earlier original transcripts stay unchanged. This document requests preparation of one original Windows admission pilot. It does not authorize execution or production support.

## Smallest useful extension

Extend only `RegistryKeyExists` (3), `RegistryEntryExists` (4), `RegistryEntryStringContent` (5), and `RegistryEntryIntegerContent` (6), under a separately versioned supplied-context schema. Keep the same bounded expression grammar, definition validation, fresh condition-result cache, lazy lookup, first-error evidence and true/false exit semantics. No registry read would occur in the eventual Python evaluator.

The source makes two distinctions that the context must preserve. Key existence is a `Registry.GetValue(path, "Test", boxed Int32 1)` query. Entry existence/content instead query the requested entry using the literal sentinel `23021957-xxx-yy-z-27331bfa-adf0-46be-8d44-18b1a831affe` as a string default. A missing key returning null, a missing entry returning the default, a present literal sentinel, and a present empty string are different observations. They cannot be collapsed into one absent Boolean before the original branch runs.

This is not the separate rollout implementation. These leaf methods call the three-argument static `Microsoft.Win32.Registry.GetValue` and do not choose `RegistryView.Registry32`. The source establishes a process-default view request. A future captured context must identify the observed provider/runtime/bitness; it must not claim the actual Toolkit launch architecture from this DLL alone.

## Exact original graph and ordering

`source-graph.json` records the historical IL identities and direct calls. The sealed common DLL is SHA256 `477fb88de310852611f26d1f845da23b8f0e6b602de8ab61a3eefc06339dc4ba`. Relevant original methods are:

| Method | RVA | Observable order |
| --- | --- | --- |
| CallbackDuringEvaluation | 0x2210 | Check successful-result cache; find lowercase definition; call EvaluateCondition; add cache only after success. |
| EvaluateCondition | 0x24f4 | Dispatch 3 to key existence, 4 to entry existence, 5/6 to entry content. Other providers are not admitted by this proposal. |
| EvaluateRegistryKeyExists | 0x2980 | Validate path; expand root; query `Test`/Int32 1 at IL0039; compare result with null; apply/reject comparator. |
| ReplaceRegistryRootAbbreviations | 0x2a14 | Sequential StartsWith tests for HKLM, HKU, HKCU, HKCR; replace first occurrence when matched. No separator check or general path normalization. |
| EvaluateRegistryEntryExists | 0x2aa0 | Validate path, then nonempty entry name; expand root; query sentinel at IL005e; null or exact ToString sentinel means absent; apply/reject comparator. |
| EvaluateRegistryEntryContent | 0x2b8c | Validate path, then nonempty entry name; expand root; query sentinel at IL0064; null/sentinel shortcut; otherwise second ToString and lowercase LHS; reject null RHS; lowercase RHS; dispatch integer or string comparison. |
| CompareInt | 0x2de0 | Parse RHS Int32 first; empty/null/sentinel LHS returns false; parse LHS; dispatch six numeric comparators. |
| ReplaceFirstOccurrence | 0x3080 | IndexOf(string), then Substring/Concat; unchanged source when no occurrence. |
| ClientConditionChecker static initializer | 0x3225 | Assign only the literal sentinel. No provider call. |

The key/entry-existence comparators are 1 (IsTrue) and 2 (IsFalse). An invalid comparator is rejected after the registry query, not before it. Entry existence calls ToString once for a non-null object and compares the exact result with the sentinel. It does not lowercase this comparison.

Entry content checks null and the exact sentinel before reading/validating the RHS. Either observation immediately returns true for comparator 11 (IsNotEqual), false for every other comparator, including an otherwise invalid comparator. A non-null, non-sentinel object receives a second ToString call. Stable primitive facts may model both calls; arbitrary objects or a stateful ToString cannot be silently accepted as primitives.

For a present object, content lowercases the LHS before rejecting a null RHS. String comparators 10/11 use Equals/negated Equals; 16 uses StartsWith(string); 17 uses Contains(string); 12/13/14/15 use CompareTo(string) with greater/greater-or-equal/less/less-or-equal. ToLower, StartsWith, IndexOf and CompareTo use culture-sensitive overloads. Equals and Contains here are the string overloads without a supplied comparer. The original does not request ordinal ordering. In particular, Python lexical order for arbitrary printable ASCII punctuation is not a justified replacement for CompareTo.

The first implementation should use an explicit invariant culture profile and retain the accepted ASCII bounds. Equality/contains can use the bounded normalized strings once their lowercase domain is established. Prefix and especially ordering need a separately reviewed primitive comparison domain or captured comparison facts; the twelve-call pilot alone will not prove all ASCII collation. Unsupported reached comparators/domain values must remain unsupported, including when a supported prefix/ordering guess would be convenient. Missing-value shortcuts must precede these reached-domain exclusions, as in the original.

## Existing 107 original Int32 observations

`integer-evidence.json` copies the exact 107 already captured direct CompareInt inputs/observations and their transcript binding. There are 76 Boolean returns and 31 ClientConditionException results; no new execution is requested for them. All 107 agree with their prewritten expectations. The containing initial batch still has its historical failed expectation flag caused by two unrelated diagnostic wording cases.

The direct helper covers all six comparators (10..15), signed Int32 endpoints, plus/minus and signed zero, leading zeros, outer spaces and the observed tab/CR/LF spelling. It records overflow, decimal/hex text, whitespace-only inputs, RHS failure before invalid/absent LHS, and invalid comparators after successful numeric parsing. The eventual finite parser must use explicit ASCII NumberStyles.Integer-like syntax and Int32 range checks, not Python's unrestricted int coercion or Unicode whitespace/digits. The full ASCII whitespace set beyond the captured tab/CR/LF/space combinations remains an explicit domain decision.

These direct helper observations must not be applied before RegistryEntryContent's outer missing-value branch. For example: a missing entry with null RHS and IsNotEqual returns true without CompareInt; a present empty string with valid RHS returns false through CompareInt even for IsNotEqual; a present empty string with invalid RHS raises the RHS error. The pilot has paired missing/empty/error cases for this distinction.

## Proposed captured-context boundary

Use an explicit new context format, provisionally `cbus-toolkit-condition-context-v2`, rather than changing how a v1 document is admitted. Keep the existing `files` field unchanged and add at most eight unique `registry_reads`. Each read identifies the exact expanded path, exact entry, exact typed default, and a tagged result (`null`, `string`, or signed `int32`). Use a separate provider declaration stating that all facts are caller supplied, the call was Registry.GetValue with its process-default view, and the reported Windows runtime/bitness is unverified input.

The lookup identity is `(expanded path, entry, typed default)`. Merely matching path/entry loses the different default behavior. Preserve the condition's raw path, the expanded query path, the typed supplied result, and the derived ToString text separately in evidence. Do not infer case-insensitive registry identity, hive alias equivalence beyond the original expansion, key existence from a value record, REG_DWORD signedness from arbitrary integers, or REG_EXPAND_SZ environment expansion. These are facts captured at the provider boundary, not a registry emulator.

An omitted requested record is unknown and stops that reached stage as unsupported, retaining prior cache/events. Null is an explicitly known result. Null or malformed metadata in an unrequested definition must retain the accepted lazy behavior. A tagged provider error may eventually retain bounded captured exception metadata as a failed observation; it must never instantiate an arbitrary exception class or present supplied exception text as a real exception caught by the current process. This first pilot does not validate provider-error parity, so that input remains unsupported initially.

Bounds remain two JSON documents of at most 128 KiB each, depth 12, at most eight definitions and eight registry-read records, expression/name and entry/RHS/result strings at most 256 ASCII characters, path at most 1024, exact duplicate-key/type validation and pre-conversion integer bounds. Registry paths and entry names in the first profile should use a conservative printable ASCII path grammar with canonical full hive roots or the four exact abbreviations followed by a backslash; excluded malformed prefixes still appear in source findings, without being guessed into a valid query. Existing v1 files and all metadata/revocation stages remain unchanged.

## Proposed Windows admission pilot: exactly twelve original calls

`pilot-cases.json` fixes twelve leaf invocations and their expected outcomes before execution. It is an admission/provider pilot, not a complete operator or all-hive matrix. One x86 .NET Framework child would invoke only the three unchanged private static leaf methods by exact name/signature/RVA identity. No public Evaluate, NCalc evaluation, instance checker constructor, full update model constructor, DownloadChannel, SesuConnect, rollout, RNG, clock, environment expansion, network or C-Gate path is called by the original test arm.

Build only plain Condition fixtures using a constructor-bypassed object and the audited auto-property setters. Record the static literal initializers and their byte hashes before the call. Reflection transport errors and guard failures are harness failures; only an unwrapped exception from the exact intended original invocation is an original outcome. A provider witness may separately call Registry.GetValue with the identical query/default once per row and record CLR type/exact text; this is explicitly a harness observation, not an intercepted original call. Query count/order claims remain source grounded, since this design does not instrument the original provider call.

Create one random, task-owned scratch root directly beneath an already-opened existing `HKCU\\Software` handle. The root's literal name and all twelve expanded case paths are frozen into the execution input before submission. `RegCreateKeyExW` must report a newly created root; an existing root is never adopted or deleted. All original input paths must be either that exact full HKCU path or its exact HKCU abbreviation, plus one whitelisted case subkey. No arbitrary hive/path input, slash rewriting, parent traversal, registry link or caller-provided native handle is admitted. Fixture construction creates no registry links, changes no ACLs, uses no HKLM/HKU/HKCR key, and records the raw kind/bytes of each value. Existing owned subkeys can be created only under the new root. Missing-key rows omit their particular subkey entirely.

The input is at most 64 KiB, read by a bounded strict UTF-8 regular-file descriptor path with no reparse/symlink components. Reject the full input before fixture writes if it differs from the sealed twelve cases. The child records IntPtr.Size=4, framework/version/assembly locations and hashes, current culture, original method bodies, task SID/session, exact command, root identity, fixture operations and raw provider observations. Set invariant culture explicitly; do not imply the original Toolkit user's actual culture. Existing Windows bridge provenance, exact vendor aliases and original inventory hashes must be verified before compile/run and unchanged afterward. The future runner must record actual loaded assembly paths/hashes, not just MVID or self-reported filenames.

No socket/client/factory construction is reachable through the whitelisted original calls. The host submits only one already compiled process through the existing owned bridge, after root releases the queue; no runner renewal or shared service change. A host/guest watchdog limits the child to 30 seconds, with a separately bounded cleanup phase. The runner preserves attempted/started/reaped independently, file-backed partial stdout/stderr, first error/interruption identity, and all admission/report write/close failures. It never resubmits a failed process.

Cleanup closes every opened registry handle and removes only known fixture values/subkeys and the newly issued owned root. Verify the final root is absent and record all cleanup results. If an unexpected value/subkey is discovered or ownership is uncertain, do not recursively delete unknown state; report the exact remaining owned path as incomplete. If force termination prevents in-process cleanup, a separately approved cleanup-only action may target the sealed root only after ownership evidence is inspected; it must not replay original cases. Report successful original calls separately from cleanup/overall success. Preserve every first failed pilot and stop on the first unexpected original or harness result rather than silently extending the run.

## What remains after this pilot

Before production admission: review the exact probe/runner and run the twelve cases; compare supplied-context branches with those native observations; prove a bounded culture-sensitive string domain or keep those stages unsupported; extend original leaf vectors for all operators, malformed paths/entry/RHS and lazy expression composition under a separate finite plan. General Windows value kinds, permissions/errors, REG_EXPAND_SZ, multi-string/binary/QWORD coercion, x64/HKLM view differences, hive/path aliases, provider timing/concurrency and public Evaluate wrapping require further evidence. Real machine applicability, rollout/install/date/media providers, publisher trust and update availability remain excluded.
