# Held CSV backend corroboration pilot

Proposed, not executed. No new package, command or generic project projection is proposed. Parent review of the concrete harness and exact admission hashes is required before original/native execution. Maximum twelve finite cases across the two stages below; stop at the first unexpected result, retain it, and do not broaden a provider or replay automatically.

## Stage A: eight original command/parser cases

Reuse the accepted local Unicorn/Capstone runtime and exact Toolkit EXE. Extend the earlier cached-class probe only in a new file: admit original command generation, QuickGet result extraction/completion, route getters, and the AgentLoad QuickGet branch. Use the actual registered agent/class pointers from source-data-v1.json. The original constructors, command transport, exception dispatch and global startup remain excluded. A strict constructor/transport provider records its exact class/arguments/callsite and delivers prewritten responses; no socket API is available in the original process. Existing fixture storage publication remains explicit.

Cases A01/A02 render the same request through nonblank OID and blank-OID path branches. A03 checks terminal315; A04 checks ordered continuation315- then315; A05 deliberately returns a different parameter name and records the original parser's name-discard behavior; A06 supplies the original completed-but-missing-parameter response. A07 applies an admitted hexadecimal value through the unchanged StrToIntDef/Area getter path, since earlier Area fixtures were decimal only. A08 exercises the actual AgentLoad QuickGet branch and confirms the returned string is written to unit+0x160 before the original getter updates the Area reference.

Each case records full supplied text, generated command, original command result/completed/exception fields, original unit/attribute/reference bytes before and after, and ordered callbacks. Prefix/suffix/command-ID formatting is explicit; if the communicator-normalized response format remains uncertain, retain both full wire and exact admitted parser argument rather than asserting they are identical. The harness must validate every echoed field/phase, not only case IDs.

Admit only exact instruction starts and bytes, including source-proved normal finally continuations. Bound input64KiB, twelve-case plan, each supplied string1024 UTF-16 units, each generated string16KiB, instructions1million/case, process90seconds, and total output4MiB. Unknown opcode/call/provider/address or a harness exception stops capture. Ordinary original return, original operation rejection, expected provider stop and harness failure have separate states. Unsupported Delphi exception unwinding stops before dispatch and cannot be reported as an original successful error return.

## Stage B: four fresh isolated-backend fixtures

Proceed only after A is captured and reviewed with unchanged harness bytes. Create a fresh LocalCGate child using the pinned original C-Gate3.4.0 build2001 JAR and explicit Java11. Its cwd/temp/config/project data reside under a new direct owned external child. Use loopback-only Clipsal access, verify all six listener endpoints and exact child PID, disable auto-open/autosave/network startup, and create only a generated project with a closed network pointed to an owned loopback reject-all sentinel. Never adopt/switch/restart the main service, use Docker, open a network, send physical commands or forward traffic. The sentinel must show zero connections/bytes for completion.

The four fixtures are: (B01) materialized RELAY4 firmware4.4 with Area12 and all referenced group metadata already present; (B02) Area255 with an existing unused-group record; (B03) Area13 whose metadata is deliberately absent, to prove a PP read does not create it and to retain the original getter's expected metadata-save dependency; (B04) a generated unknown unit-type scalar record, to corroborate native XML field preservation and generic class selection without pretending it has a valid PP specification.

Setup writes are explicit and occur only before the recorded read boundary. Materialize RELAY4 with native PP NEW/SET/SAVE in the owned project, close the programming session, save/close/reload the project and capture all PP/raw database XML. Reject a setup failure rather than adapting the source or firmware silently. Query native PP GET_UNIT_SPEC RELAY4.xml once and compare the relevant parameter definitions with the pinned prior plaintext input; mismatch stops before dependent work.

Within each materialized read boundary, execute the literal original lowercase PP QuickGet command against the observed OID and equivalent declared database path, recording full tagged wire bytes and client-normalized lines separately. Query AreaGroupAddress, Application and GroupAddress; only B01 also captures the six LogicGA association arrays needed for the later cold-cache phase. Read database identity through DBGET/DBGETXML. Do not open a PP write session, set parameters, save a project, create metadata, or perform a recovery mutation during this boundary. Record the closed network, session inventory, full PP and XML before/after. Any unexpected changed field is a finding and stops the pilot; an ACK is not evidence of read-only behavior.

Feed the captured exact response text to the already reviewed original parser/getter harness with no new instruction/provider admission. For B03, the original GroupByAddress creation/save branch must stop at its rejecting provider. Preserve the partial in-memory allocation/reference history separately; the native database must still lack the group. For B04, use native scalar strings as explicit cached facts and record generic selection/zero Area QuickGets; do not claim full XML importer execution or load undefined PP data.

Native commands have finite per-command deadlines and bounded tagged framing. Record every command and response, including definite rejection and partial transport output. Allow only the exact generated project/network/unit addresses, expected read commands and previously admitted setup/cleanup commands. No shared/global repository selection. The native driver preserves first KeyboardInterrupt/SystemExit objects, uses file-backed child logs, retains independent cleanup errors, and does not run further original/native diagnostic operations after an interruption. Child stop/exit/listener teardown and artifact hashing are required for overall completion; cleanup failure cannot leave passed=true.

Before execution, archive exact driver/probe/case/helper/source/runtime inputs. After both success and failure, host-only guarded posthashes and partial artifact hashes run without replacing the first error. Do not delete evidence. Every original/native input, command sequence and phase association must be validated against that case's immutable data.

## What success would establish

Success joins the native PP literal/identity/response behavior to the original result-to-Area path for generated fixtures, and establishes whether these particular materialized reads preserve database state. It exposes the missing-group save requirement and generic unsupported-spec boundary. It does not establish arbitrary XML parsing, whole Toolkit startup, all registered class histories, all unit families, hardware behavior, event monitoring, or a full cold-cache report command.

The following separate step would use the captured DBGETXML documents in an original cached-import/attribute-setter harness, then original LoadApplications/LoadDatabaseUnitGroups and relay channel preparation. That step must compare constructor attribute names, OIDs, address/reference identity, ordered duplicates and all exported scalar strings; it must preserve any unknown-group creation dependency. Only after those phases compose should we propose native `document database` output using the existing portable UTF-8 serializer. This avoids another public command limited to the earlier synthetic twelve patterns.
