# Registry conditions v2: authored source archive

This directory preserves authored research and acceptance sources for the completed registry extension. It is a source archive for review and reconstruction, not a standalone reproduction bundle. Exact historical paths, prefixes, gates and prepared-state labels are preserved. Do not replay its one-use Windows identities: the reviewed jobs already completed, and the original scratch root was removed.

The `pilot/` sources prepared and ran one separately authorized original Windows pilot: **12 unchanged original leaf calls**, 12 separate same-provider witness reads and 47 ordered records. Ten calls returned their expected Boolean and two returned their expected original error. All 11 issued child keys, the owned root and handles were cleaned. The v2 dependency addition was the exact already-staged Microsoft.Win32.Registry 5.0 type-forwarding facade. It did not replace original types or methods. `provider-provenance.json` records the resolved provider identity and references the preserved report/audit hashes without copying raw VM output.

The `acceptance/` sources ran **78 supplied-fact tests on each of Python 3.13 and 3.10**, with no failures, errors or skips. Those runs performed no original Windows or registry execution. They comprise 17 new registry core/CLI tests plus 61 existing conditions/metadata/revocation regressions. The comparison coverage is 11 supported original registry observations, **one explicitly excluded culture-sensitive comparison** (`Z > a`), 107 separate captured CompareInt observations, and 248 byte-identical complete v1 reports. The 78 test count must not be described as 78 original Windows cases.

`context/PROPOSAL.md` specifies the supplied-fact v2 schema and HKCU-only domain. `capture_v1_corrected.py` is the pre-edit compatibility capture. `dependency/inspect.py` is the preserved initial metadata-inspection source; it originally made an incorrect zero-total-method assertion. `classify.py` corrected that classification using the already captured metadata: the facade has resource/compatibility helper methods, but no Registry.GetValue implementation. The separate earlier registry-v1 failed dependency pilot, initial invalid-context baseline and pre-test optional-runtime inventory failure remain historical failures, not retroactively successful runs.

Included files are explicitly selected authored C#/Python, finite ordinary case inputs, plans and hash/identity contracts. No vendor DLLs, installers, compiled probes, disassembly listings, registry dumps, raw VM stdout/stderr, private keys, credentials or runtime archives are included. The Windows SID, method metadata tokens, public-key identity token, SHA-256 pins, local source paths and one-use scratch names in these sources are ownership/provenance identifiers, not authentication secrets. Full proprietary dependencies and raw execution evidence remain at the external locations referenced by the manifest and accepted fixture.

`source-copy-manifest.json` lists each copied file's original path, hash and byte count, plus generated-summary hashes. Existing `registry-pilot/` and `registry-proposal/` snapshots were left unchanged. No scripts were executed from this archive while preparing it. The accepted product documentation is `docs/toolkit-update-registry-conditions.md`; its compact checkpoint is `research/fixtures/toolkit-update-registry-conditions-acceptance.json`.
