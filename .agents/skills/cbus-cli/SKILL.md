# C-Bus CLI

Use the Python Toolkit CLI for project and commissioning workflows, and the Rust tools for MQTT bridging, protocol inspection, and test servers. Both are maintained products.

## Start with the task type

- For Toolkit project editing, commissioning, device configuration, and Python installation, read [references/toolkit.md](references/toolkit.md).
- For exact commands, arguments, outputs, and exit behavior, read [references/cli.md](references/cli.md).
- For crate responsibilities, data flow, project files, and MQTT behavior, read [references/system.md](references/system.md).
- For C-Gate commands, sessions, wire framing, and the Toolkit compatibility boundary, read [references/cgate.md](references/cgate.md).

## Operating rules

1. Work from the repository root and run Cargo commands with `--manifest-path rust/Cargo.toml`, or change to `rust/` first.
2. Treat `--help`, the current Python and Rust source, `toolkit-cli/docs/`, and `docs/` as authoritative. Do not confuse the active Python Toolkit CLI with the retired Python bridge implementation.
3. Select the program for the job. Use `cbus-toolkit` for project editing, commissioning, supported device configuration, and C-Gate client workflows; `cbus-tools` for small Rust inspection utilities; `cmqttd` for the bridge; and the appropriate simulator for tests.
4. Install `cbus-toolkit` with Python 3.13 or newer into `toolkit-cli/.venv`. Rust binaries live under `rust/target/release/` after a release build. During Rust development, use `cargo run --manifest-path rust/Cargo.toml -p <package> -- <args>`.
5. Start with committed fixtures, a simulator, or an ephemeral loopback port. Use a physical endpoint only when the user supplied or selected it.
6. Distinguish observation from mutation. Toolkit project edits write files; online C-Gate and PCI commands may change a server or physical devices. `decode`, `dump-labels`, and vector checks are local reads. `interrogate` sends C-Bus requests. `cmqttd` accepts commands that can control a connected network. State-changing commands against `cgate-mock` affect only its in-memory model.
7. Never invent endpoint addresses, project names, credentials, certificate paths, unit addresses, or network names. Read them from the user's command, existing configuration, or project data.
8. Preserve ignored site files and secrets. Do not print authentication files, private keys, or project contents unless the task requires that exact output.
9. Report the command used, its exit result, and the relevant output. When the command can affect hardware, state which endpoint was targeted.
10. For eDLT Measurement decimal Gain/Offset values, never infer a locale from the host. Keep the default `canonical` grammar or choose one of the source-pinned Toolkit profiles explicitly, then inspect exponent-wrap metadata before applying the plan.
11. When one edit needs both a Measurement panel and the proximity percentage/action control, use the bounded `edlt parent-form-plan` or database `edlt-parent-form` workflow with explicit lifecycle metadata. Inspect its phase, cross-control and preservation evidence. Do not turn its source-pinned order into a claim that the complete original WinForms parent executed.
12. When one KEYGL5 5.5.00 edit needs several supported panels, use `edlt parent-transaction-plan` or database `edlt-parent-transaction` with an ordered JSON operation file. The admitted operations are Measurement, Lighting, Enable, Fan, HVAC, Multi Level, Room Courtesy, Scene, Shutter, Time/Date, Timer, MRA Zone Control, Source Select, Source Control, activation, General, Display, Standby, Colours, Navigation, Quick Status, Page Control and MRA globals. Put enabling panels before dependent panels: Display before an HVAC/MRA icon edit, Standby before idle Colours controls and a retained or newly created MRA widget before `mra-globals`. Treat multiplexer and zone as independent single-owner shared fields; omission consumes the first existing pre-conversion MRA values, including stored standby/raw3 state. Inspect complete record/field/shared-bit ownership, operation metadata dependencies, results, terminal lifecycle fields and execution counts before applying. Never split an intended one-save edit into standalone saves, reuse a widget slot, overlap the second half of a two-slice Time/Date widget, or describe retained component evidence as an executed original multi-panel form. Applications/Corridor cache dialogs, Blank/Reset and SceneManager remain separate workflows. If SAVE fails or is interrupted, treat `saved=false` as unconfirmed persistence and do not retry the uncertain operation.
13. For that parent transaction, prefer `--project-xml ... --unit ...` offline or `--auto-metadata --exclusive-project` on an existing database unit when one exact native project snapshot is authoritative. Inspect every planned application/group creation, dynamic-variant fact and the 64-slot static-label inventory. Manual caches need explicit positive evidence for every operation-introduced group; explicit dynamic text/icon assignments also need matching four-variant image facts. Make `--lock-address` exactly name the selected source network, keep every project network closed and give the command exclusive project ownership. C-Gate does not atomically commit DBADDSAFE, PP SAVE and PROJECT SAVE: rollback is automatic only before PP SAVE starts. Never retry or restore automatically after a PP/project save attempt. Use the caller-cache path when consumed DYNAMIC/FONT/ICON facts require project or DLTP images that DBGETXML cannot establish.
14. For retained SceneManager edits, use `--project-xml ... --unit ...` offline or `--auto-metadata --exclusive-project` on the database command when native metadata is authoritative. Inspect `planned_creations`: retained getter accesses can create missing application202 as `Trigger Control`, exact non-255 trigger groups as `Group N`, and exact actions as `Action Selector N` with Address=Value=N and four blank variants. This is the automatic nonblank exact-address path; the separate accepted Add dialogs are not implemented, including their first-free 0..254 `Level N` seed. It admits the fresh original network-model default `bAdd=true`, not a prior Toolkit process session in which an auto-add prompt was declined. Never infer an image-dependent label. Keep the exact source-network lock and every project network closed/idle. On apply, prefer a reviewed `--backup-project`; DBADDSAFE/DBSETSAFE, PP SAVE and PROJECT SAVE are separate. Automatic rollback deletes known objects in reverse level/group/application order only before the first applicable PP or target-project save, and no uncertain save may be retried. Complete SceneManager control binding remains unsupported.
15. cmqttd's maintained C-Gate CONFIG family is local command-compatibility state. Read catalogue values with GET/INFO/OBGET; use SET/OBSET/OBRESET/LOAD/SAVE only when a durable cmqttd-internal override or snapshot is intended. A CONFIG filename is an internal snapshot identity, and CONFIG values never reconfigure the running listener, PCI, MQTT, logging, or host files. Read [references/cgate.md](references/cgate.md) before using its scoped inheritance or LOGIN-gated mutations.
16. cmqttd's maintained C-Gate FILE family uses a durable virtual root in `cmqttd-json`. Use DIR/LS, MKDIR, DELETE, SHA256, DOWNLOAD, and native base64 here-document UPLOAD with relative paths. Treat `%PROJECT%` as a virtual namespace. Never describe FILE paths as host paths or vendor project files; `file_host_filesystem: false` is an intentional boundary. FILE UPLOAD, DELETE, and MKDIR require LOGIN when the gate is armed. Read [references/cgate.md](references/cgate.md) for exact framing and response codes.
17. cmqttd's maintained C-Gate ACCESS family is durable local security state. Use `LOGIN` to query the session level, `LOGIN USER PASSWORD` for a native ACCESS user, and ADD/DELETE/LIST/LOAD/SAVE for policy administration. LIST deliberately returns `<redacted>` for user passwords. LOAD/SAVE names are internal snapshot identities, never host files; missing LOAD and unsafe names return 408 without replacing the active policy. An unresolved interface/remote name is rejected before insertion. Fresh and pre-ACCESS state keeps Docker/NAT clients compatible until an address rule is changed; explicit address policy then applies, with a LOGIN/LOGOUT-only recovery session for unmatched peers when `--cgate-auth-file` is configured. Use its one-token LOGIN as the operator recovery credential, or authenticate with a Clipsal/Max ACCESS user from an admitted connection, before ACCESS mutations. Never print a site password or token in a report.
18. Treat `PROJECT DIRFULL`, the three `DBGETJSON` NAC projections, `EVENT_CHANNEL`, and advisory `LOCK`/`UNLOCK` as local command-session/database behavior. NAC object and routing documents are empty until cmqttd retains vendor NACObjectList definitions; TAGMAP covers modeled local tags only. EVENT_CHANNEL subscriptions and advisory locks belong to one connection and disappear with it. Advisory locks are separate from PP locks. Inspect the matching capability fields before asserting a broader scope.
19. cmqttd's PP catalogue, lock/session inventory and raw-memory diagnostics are local compatibility operations. Supply private decoded specs only through `--cgate-unitspec`; PP file arguments must be bare names under that directory. Treat SET_RAW_DATA and LOAD_FROM_FILE as staged session edits, not device writes. PROGRAMMER and DEPLOY_QUEUE are runtime-only. START/ADD acknowledge asynchronous execution through the existing PP/DALI backends, stop on the first fault and never replay automatically; RETRY is the sole explicit re-execution operation. Inspect STATUS/LIST and the ended/debug events before reporting an outcome. `PP WRITE_PATCH` is physical only for a selected strict `cmqttd.pp-patch/v1` manifest in the controlled FILE namespace. Firmware bounds use native case-sensitive lexical order, optional catalogue metadata must match, blocks occupy at most the effective 136 bytes in ranges 114–241 and 247–254, the version parameter is `0xF2`, and parameter `0xF7` uses the returned unlock challenge as its STORE tag. Inspect `SIMULATE`, copy its SHA-256 into `EXPECT_SHA256=<64hex>` for a bound physical run, and never retry an incomplete patch until the PCI has reconnected. A normal run requires an admitted current version; an already-target recovery is read-only when blocks/control match and repairs only enable otherwise. Recovery from temporary version `FF` must explicitly list `FF` in the same reviewed manifest; `FF` is never a target version. The three success dispositions are full pipeline, repaired enable only, and verified read only. The proprietary Schneider `patchset.zip` container is unsupported; never present a native archive, PP SAVE, or simulation as a successful patch. Read [references/cgate.md](references/cgate.md) for the schema, syntax, authentication, status envelopes and retained evidence.
20. Raw `cbus-toolkit cgate exec` and `cgate run` forward the selected server's command surface; they do not establish typed Toolkit workflow parity, GUI state, native-server semantics, or a physical effect. For live eDLT acceptance, prefer `edlt-label-audit`: it joins one fresh serial inventory, serial-bracketed physical images, CRC-checked labels and cached WidgetGroups, and it excludes transient dynamic-label observations from fingerprints. Treat its baseline as a software checkpoint rather than proof of rendering, device cache contents, atomic multi-device state or power-cycle persistence.
21. cmqttd implements `REPOSITORY USE 1`, `PROJECT REPAIR`, and all five TRANSFORM leaves for its own atomic JSON repository and versioned portable SQLite container inside FILE. Do not present these as Schneider repository/archive/schema interoperability. Physical `ACCESS_CONTROL CLOSE/LOCK` covers direct application 213 only; success proves confirmed delivery rather than door/controller state, and TLS client certificates are not mapped into ACCESS rows.

## Compatibility language

Describe `cgate-mock` as providing full C-Gate 3.4 **command-surface compatibility**: all 431 unique maintained command paths parse and dispatch, core workflows are stateful, and specialist or hardware-facing families have deterministic protocol-shaped behavior. Do not claim that it is the Toolkit GUI, Schneider C-Gate, persistent storage, a physical bus interface, or an exact simulation of every device side effect and timing characteristic.

`cbus-toolkit` is the user-facing Python CLI, with offline project editors and online workflow implementations. It targets Toolkit 1.18.0.2754 / C-Gate 3.4.0.2001. Full Toolkit parity remains unfinished: consult its feature ledger and `coverage --require-complete`. The Rust mock's command coverage does not establish the Python CLI's complete workflow or hardware compatibility.

`cmqttd --cgate-bind` is the real embedded C-Gate service alongside MQTT. Read
`docs/cmqttd-cgate.md` and query `CMQTT CAPABILITIES` for its supported backend.
Its 431-path primary matrix is 230 physical, 199 local/session, zero blanket
fail-closed 502, and two native-obsolete paths, so all 429 non-obsolete primary
paths are routed. Keep `full_cgate_compatibility: false`: selector-specific
refusals, private vendor formats, device/topology/timing behavior, exact access
policy and broad hardware acceptance remain. For live KEYGL5 labels, use
`cbus-toolkit cgate edlt-labels` against this service; Windows is unnecessary.
Keep saved database labels distinct from CRC-verified physical reads and
the bounded current-connection dynamic-label observations. The observation
view is incomplete and does not read labels that were already cached by a
device.

## Changing the repository

Keep behavior in the owning Python module or Rust crate and add tests at the narrowest useful layer. Use a golden vector when exact bytes or JSON define compatibility, and a system test when correctness depends on multiple components. Run the applicable Python or Rust validation from `AGENTS.md`. Preserve Toolkit source, tests, feature documentation, and acceptance evidence during cleanup.
